<h1 align="center">世界编年史（World Chronicle）</h1>

<p align="center">
  <img src="assets/poster.jpg" width="420" alt="世界编年史 海报">
</p>

新手请看 [使用说明](使用说明.md)。每个版本改了什么见 [更新说明](更新说明.md)。

SillyTavern 扩展，用来跑“大世界”历史卡：**大事件按故事日期固定发生，每个角色因为自己的位置和背景面临不同的难题，角色的抉择沿关系网传导给其他人**（类似《巫师3》的网状叙事）。user 始终是自由的：插件注入的是“世界状态 / 人物身上的压力 / 摆在面前的难题”，从不写“剧情必须如何发展”。

插件只是一个平台，本身不带任何历史内容。时代内容做成**事件包**，由卡作者在插件自带的**日历编辑器**里填写，可以导出成 JSON，也可以直接写进角色卡，玩家导入卡后自动加载。

---

## 安装

1. SillyTavern → 扩展（拼图图标）→ **Install extension**（从 Git 地址安装）。
2. 填入本仓库地址：`https://github.com/wojiaoxiaojiuli-blip/WorldChronicle`
3. 安装后在扩展面板里能看到「世界编年史」抽屉。

要求：较新的 SillyTavern（见下文“与 SillyTavern 的接口”）。

## 玩家：快速上手

1. 打开一张角色卡，进入聊天。
2. 卡里带着剧本的话，插件会自己装好并用上，右上角会弹出一句提示。没有的话，打开「世界编年史」面板：在「剧本」那一格点 **导入剧本文件** 或 **加载示例剧本**，再回「概览」在 **使用的剧本** 里选它。
3. 像平时一样聊天。AI 会在回复末尾悄悄写一个小标记，比如 `<time>1997-07-02</time>`，告诉插件故事走到了哪天（这个小标记在聊天里看不到）。日子不对，可以在面板的 **故事日期** 里自己 **改日期**。
4. 面板顶上有一排分组：**概览**（故事里今天是哪天、时代气氛、倒计时、使用的剧本）、**在场**（谁在场，可以手动改）、**音乐**、**期刊**、**记录**（大家做过的选择、记下的小纸条、一个人的选择对身边人的牵连）、**剧本**（编辑、导入、示例）、**设置**（高级设置，还有 **AI 这一轮会收到什么**）。点哪组看哪组，下次打开还停在那一组。
5. 每个聊天的进度分开保存（存在聊天自己的资料里），换一个聊天互不影响。
6. 想看接下来会发生什么：扩展菜单（魔杖）里的 **玩家日历**（打开期刊后叫 **日历和期刊**），或者输入框左边的小日历图标。
7. 背景音乐：作者贴了网址的歌，直接就能听。剧本里只写了歌名的话，要你自己在面板的“音乐”里打开 GD音乐台（见下文）。

## 作者：工作流

在面板里点 **编辑日历和剧本**。全是填空，不用写代码。最少只要三步：给剧本起个名字、选故事从哪天开始、在日历上点一天写下发生了什么并写上它影响谁。别的都不填也能玩，它们都收在各处的“更多”里。

| 页签 | 做什么 |
|---|---|
| **日历** | 点某一天，写下那天发生的事；点已经写好的事，就能改。 |
| **角色与关系** | 故事里有谁、各是什么身份、谁和谁是什么关系。 |
| **时代气氛** | 像那段日子的天气：把故事分成几段，写下每段大家的心情（不填也行）。 |
| **小插曲** | 偶尔随机冒出来的街头小事（不填也行）。 |
| **音乐** | 贴链接 / GD音乐台 / AI 搜歌，见下文。 |
| **设置** | 名字、作者、简介、开始日期、倒计时；“高级”里能改日期的显示样子、年号、编号和版本。 |

一件事默认只要填：标题、日期、发生了什么、影响谁（对TA的影响、TA要做的选择）。“影响谁”直接写人名或身份就行，新身份会自动加进去。风声（事前的传言）、事后的议论、背景音乐、玩家日历上怎么显示、要满足什么才发生、发生后留下的小纸条，以及“如果历史被改变”，都在 **更多选项（都可以不填）** 里。

小纸条就像一张便签，提醒故事“这件事已经发生了，而且改变了后面的事”；别的事可以看有没有这张纸条，再决定发不发生。

“更多选项”里还可以勾 **只告诉 AI 一次**：AI 回复过一次之后，就不再把这件事发给它，适合“拿到成就”这种说一遍就够的事。重新生成或滑动时会再发一次，不会丢。

做好以后怎么分享：

- **保存**：存在你自己的酒馆里。如果这张卡还没选剧本，会顺便帮你选上。
- **写入角色卡**：把剧本写进这张卡里（存在卡的 `data.extensions.world_chronicle`）。分享这张卡时剧本跟着走，别人打开卡就自动用上。内容改过时版本号会自动加一，别人那边的旧版本会被换成新的。
- **更多 ▾**：从角色卡读取、导出文件、导入文件、删除这个剧本。

### AI 帮我写

手上已经有角色卡、世界书或设定？可以让 AI 先打个草稿，你再在编辑器里慢慢改。按钮在编辑器顶上（**AI 帮我写**），空剧本的小引导里也有。全在一个页面里，从上往下做：

1. **素材**：把设定贴进大框里；或者点 **读取当前角色卡**，插件会把卡的名字、描述、性格、场景、开场白和世界书条目（卡里带的世界书和卡绑定的世界书）都填进去。可以再写一句想要什么（时间范围、想要哪些事、什么语气）。框下面会显示素材大概多长，太长了会提醒你。
2. **写哪部分**：全部 / 只写事件 / 只写小插曲 / 只写角色与关系。剧本里已经有的角色和事件会一起告诉 AI，所以新写的事可以直接影响已有的人，也不会重复。
3. **怎么生成**：
   - **用酒馆当前连接的 AI**：用你平时聊天的那个 AI 直接写。素材会发给这个 AI 服务，和平常聊天一样会花额度。插件不读取、不保存、不发送任何 API 密钥，请求是酒馆自己发出去的。写的过程中可以取消；没写成会告诉你原因。“更多”里可以调 AI 最多写多长（按 tokens 算，默认 8000）。
   - **用别的 AI**：点 **复制提示词**，粘贴给任何一个聊天 AI（网页版也行），再把它的回复整段贴回来，点 **读取回复**。这条路插件不联网。
4. **看结果再决定**：AI 写的东西不会直接改你的剧本。先给你看个总结（每部分写了多少、日期和标题的列表、有问题的地方和小提醒），然后你选：
   - **加入当前剧本**：只往里加，不盖掉你已经写好的。编号撞了，会给新的改个名；同名的角色当作同一个人，只补上别的叫法和身份；同一天同标题的事会跳过；剧本名字、简介、开始日期，只有你还没填时才用 AI 写的。
   - **替换**（会再问你一次）：用 AI 写的换掉整个剧本，或者只换掉你选的那一部分。剧本编号、版本和音乐设置还是用你的。
   - **放弃**。

   加入或替换之后会回到日历，像平常一样检查、修改，点 **保存** 才会真的存下。

提示词里要求 AI：写处境和压力，不写剧情走向；玩家始终自由，不替玩家设定身份；不决定任何角色对玩家的感情；文字短、紧扣当天，不复述世界书；只用素材支持的内容，没把握的历史不当事实写；会剧透的事件用 `visibility` 藏起来；`bgm` 只写歌名不写链接。

AI 的回复被当作不可信的数据：只用 `JSON.parse` 解析（会先修正代码块、前后的说明文字、尾逗号、弯引号、注释等常见毛病），从不执行；显示时一律当纯文本；回复里的链接（`url`）除非原样出现在你贴的素材里，否则一律去掉。

同一个剧本可以用在好几张卡上。每张卡还能单独调整（面板「在场」里的 **这张卡的角色对应**）：你（user）扮演剧本里的谁（这个人只描述处境，AI 不替 TA 做决定）；给剧本里的人补上别的叫法或身份；加入卡里独有、剧本没写的人；哪些人勾上“常驻”，在这张卡的所有聊天里都一直算在场。

## 注入的内容

每次生成前，插件用 `setExtensionPrompt` 注入一段文字（位置 / 深度 / 角色可在“高级设置”中调）：

| 层 | 何时 | 内容 |
|---|---|---|
| 氛围 | 常驻 | 阶段基调、倒计时、余波期内事件的一行摘要 |
| 新闻 | 预兆期 / 当天 / 余波期 / 时间跳跃补发 / 插曲 | 预兆期**只有风声**；当天是新闻；余波期是摘要；跳跃中错过的事件补发一次 |
| 个人 | 受影响的角色**在场**时 | 压力、难题（含事件 id 与参考选项）、已作出的选择、来自关系网的牵连 |

规则：

- **防剧透**：事件在预兆期之前完全不出现；预兆期内只出现风声，不出现新闻，也不出现个人层的压力 / 难题。
- **时间跳跃不漏**：从旧日期到新日期之间到期的所有事件都会触发；如果新日期已经越过某事件的余波期，它会进入“补发队列”，在下一次真实生成时注入一次（标记为已读），再下一次推进日期时清除。
- **首次设定日期**：在此之前的事件视为“历史”，不补发新闻，但它们设置的旗标会生效。
- **回拨日期**：撤销新日期之后的触发记录（用于纠错）。
- **在场判定**：最近 N 条消息（默认 4，含发言人名字）中出现角色名或别名；面板里可以手动覆盖。

## 标签约定

插件会在注入里要求 AI 这样做（可在高级设置中关闭这段约定）：

```text
<time>1997-07-02</time>
<choice who="陈伯坚" event="baht">撤出港股资金</choice>
```

- `<time>`：回复末尾标注故事内当前日期，一律写公历（剧本用共和历之类显示时也一样）。也接受 `1997-7-2`、`1997/7/2`、`1997年7月2日`；一条消息里有多个时取最后一个。
- `<choice>`：在场角色对难题作出选择时输出。`who` 可以写名字、别名或 id；`event` 可以写事件 id 或标题。同一角色对同一事件只保留最新一次选择。只有当在场的非 user 角色有待决难题时，注入里才会出现这条约定。
- `<bgm>`：按事件包的“AI 怎么选歌”（`off` / `playlist` / `free`）出现在约定里；玩家关掉 BGM 总开关时不出现。见下方“背景音乐”。
- `<flag>`：剧本在“设置 → 高级 → 会改变历史的转折”里列了旗标时出现在约定里。剧情真的走到那一步时 AI 输出 `<flag>某人幸存</flag>`，插件记下并弹出提示，可在“世界记录”里撤销。不在列表里的名字会被忽略。转折可以设最早和最晚日期：只有这段时间里 AI 才会看到它，也才会被记下；手动在面板里加不受限制。
- 日期保险：AI 写的日期一次往前跳超过 180 天（可在“设置 → 高级”里改）、越过 8 件以上事件，或往回跳超过 7 天时，插件会先弹窗问你，选“保持现在的日期”就不动。
- 这些标签在显示时都会被隐藏（原文仍保存在消息里，AI 下一轮看得到）。user 自己的消息里写这些标签同样生效，可用来手动“跳到某天”。
- **滑动 / 重新生成 / 继续 / 编辑最后一条消息**：插件会先恢复到这条消息之前的世界状态，再按新内容重新处理。

## 背景音乐（BGM）

### 作者：音乐从哪来（三选一）

在编辑器的“音乐”页选一种：

| 方式 | 作者要做的 | 玩家要做的 |
|---|---|---|
| **贴链接** | 把音乐传到图床或网盘，贴上音频直链 | 什么都不用做 |
| **GD音乐台** | 只写歌名（`歌手 - 歌名`） | 同意开启 GD音乐台一次 |
| **AI 搜歌** | 什么都不用准备（可以写几首推荐） | 同意开启 GD音乐台一次 |

- 批量粘贴时每行一首：`歌手 - 歌名 | 链接 | 氛围`，只有歌名或只有链接也可以（只有链接时用文件名当歌名）。
- 链接必须是能直接播放的音频直链。网易云、B 站这类网页地址放不出声音，编辑器会提示。贴好后点 ▶ 试听。
- “贴链接”和“GD音乐台”可以勾选“让 AI 按气氛从歌单里选歌”；不勾选时只由事件、时代气氛、小插曲和关键词切歌。
- 事件、时代气氛、小插曲的“更多”里可以绑定一首歌。“关键词切歌”在音乐页底部，默认收起。

### 触发优先级

AI 的 `<bgm>` 标签 > 关键词 > 刚发生的事件 > 刚抽中的小插曲 > 进入新的时代气氛。都没有时保持当前曲目。

### 玩家

设置面板有**背景音乐**总开关（玩家日历里也有）：关闭后不播放、不发任何请求，也不让 AI 选歌。

每首歌依次这样找：作者贴的链接 → GD音乐台（剧本用它、且玩家同意过）→ 只在右上角显示“此刻配乐”和网易云搜索链接。需要 GD音乐台但还没开启时，右上角的提示里可以一键开启。

**GD音乐台**是第三方公开接口，默认关闭，开启前必须本人确认声明，作者的剧本不能替玩家打开：仅限个人学习，不得再分发或商用；资源来自第三方，版权归原权利人；开启后你的 IP 和歌名会发送到 `music-api.gdstudio.xyz`；播放时一直显示“音源：GD音乐台(music.gdstudio.xyz)”。播放地址带时间戳会过期，只在内存缓存约 10 分钟；接口限制 5 分钟 50 次，插件在本地计数，接近上限或出错时会暂停请求。

**自动播放限制**：浏览器不允许页面在用户还没点过的时候出声，被拦截时会弹出提示，点一下就开始播放。

## 玩家日历

扩展菜单（输入框左边的魔杖图标）里有 **玩家日历**；输入框左侧默认也有一个日历图标（可在面板「设置」里关掉），面板「概览」里也有按钮。打开期刊后，同一个弹窗上方可以切换“日历 / 期刊”。它是只读的弹窗：

- 当前故事日期、阶段、倒计时；
- 月历：今天高亮，有事件的日子带标记，点某天看当天的事件；
- 即将发生的事件（几天后）、已经发生的事件、最近的世界记录；
- 此刻配乐 + BGM 开关；“显示未来事件”开关（默认开）。

**防剧透**：作者可以给每个事件设置“玩家日历里”的可见度（`visibility`）：`show` 显示标题与摘要（默认）、`title_only` 只显示标题、`hidden` 发生前不显示。玩家关掉“显示未来事件”则只看已经发生的。事件发生后总会显示。**这只影响玩家界面**，不影响注入：AI 本来就永远看不到未到期的事件。

## 定期刊物

故事世界里按日子出刊的小报。到了出刊日，插件**另起一次** AI 调用写一期，存在聊天里，在单独的弹窗里看，不混进正文。

- **总开关默认关闭**，玩家在面板“期刊”里自己打开；每本刊物单独开关；“出刊提醒”开关控制小红点和提示。
- **附赠小样《玉郎闲话》**：女尊世界通用的男子风尚秘刊（每月初一、十五出刊，粉红洒金笺），**含成人向内容**。没选剧本也能用。
- **入口**：期刊和日历共用一个弹窗，上方切换“日历 / 期刊”。从输入框旁的日历图标、扩展菜单“日历和期刊”、面板“看刊物”按钮、日历里出刊日的小报图标都能进。当前期没看过时，日历图标上亮“新刊”小红点。
- **日期来源**（依次回退）：剧本的故事日期 → 最近消息里的 `<time>` → 玩家在弹窗里手动写。出刊日 = 日期的“日”在 `schedule.days` 里；当前期 = 不晚于故事日期的最近出刊日。看不到未来的期。
- **设定覆盖**：当前卡的世界书里有注释（名字）等于刊名或刊头的条目，就用它作刊物设定，否则用刊物自带的。
- **给 AI 的素材**：刊物设定 + 卡内嵌与绑定的世界书（字数上限可调，默认 6000）+ 最近 N 条聊天（默认 20）+ 剧本截至出刊日已发生的事件、风声与时代气氛。**不给未来事件**。
- **输出格式**：`§头条§ …` / `§栏目名§ …` 逐行；也认 `{ headline, columns }` JSON；都不是时把原文放进一个无名栏目照样显示，并提示可以重写。
- **存储**：`chatMetadata.world_chronicle_periodicals = { issues: { 刊物id: { 日期: { text, createdAt } } }, read: { 刊物id: 最近看过的期 }, manualDate }`。可翻往期、可“重写这一期”。

剧本里的格式（可选字段，旧剧本没有它照常加载）：

```jsonc
"periodicals": [
  {
    "id": "evening", "name": "城南晚报",
    "schedule": { "days": [1, 15] },          // 每月几号出刊
    "profile": "码头工人办的小报……",           // 刊物设定（写给 AI）
    "columns": [{ "name": "码头新闻", "note": "进出港的船和货" }],
    "specials": [{ "month": 12, "days": [15], "name": "年终大盘点", "note": "……" }],
    "title": "城南晚報", "subtitle": "码头人自己的报", "footer": "每份两个铜板",
    "theme": "plain",                         // plain 素白小报 / pink-gold 粉红洒金笺
    "enabled": true, "adult": false
  }
]
```

与附赠刊物同 `id`（`yulang`）时，剧本里的会替换附赠的。编辑器的“期刊”页签可以填空式编辑。

出刊日计算、提示词拼装、结果解析、HTML 渲染（只用行内样式）、往期存取都在 `engine/periodicals.js`，不依赖 DOM 和 ST 全局，打算以后原样搬进酒馆助手脚本。

## 事件包格式

编辑器会生成并校验这个格式，一般不需要手写。完整例子见 [`packs/thermidor/thermidor.json`](packs/thermidor/thermidor.json)。下面的例子是虚构的，只用来说明字段。

```jsonc
{
  "meta": {
    "id": "hk-1997",                 // 必填，唯一
    "name": "香港·九七前后",
    "version": "0.1",                // 写进卡里的包靠版本号决定是否更新
    "display": "{y}年{m}月{d}日 星期{w}",
    "eras": [{ "name": "民国", "from": "1912-01-01" }],   // 可选，配合 {era}{ey}{cey}
    "start": "1997-06-20",           // 起始日期（AI 还没输出日期时作为提示）
    "countdowns": [{ "label": "距离回归", "date": "1997-07-01" }],
    "interlude": { "every_days": 3, "chance": 0.7 },      // 插曲抽取间隔与概率
    "ripple_days": 30                 // 涟漪有效期，0 = 永久
  },
  "tags": ["金融从业者", "外来者"],
  "characters": [
    { "id": "shao", "name": "陈伯坚", "aliases": ["陈生"], "tags": ["金融从业者", "外来者"], "note": "" }
  ],
  "relations": [
    { "from": "shao", "to": "ye", "type": "客户", "note": "陈伯坚是小叶的大客户" }
  ],
  "phases": [
    { "id": "eve", "name": "回归前夜", "from": "1993-01-01", "to": "1997-06-30", "mood": "……" }
  ],
  "events": [
    {
      "id": "baht", "date": "1997-07-02", "title": "泰铢放弃固定汇率",
      "lead_days": 0, "linger_days": 14,
      "rumor": "", "news": "……", "summary": "余波期显示的一行（可选）",
      "affects": {
        "金融从业者": { "pressure": "……", "dilemma": "……", "options": ["……"],
                        "ripple": "{who}决定{choice}，{target}受到牵连（{type}：{note}）" },
        "ye": { "pressure": "……" }
      },
      "set_flags": ["某旗标"],
      "if": null,
      "variants": [
        { "if": { "choice": { "who": "shao", "event": "baht", "is": "撤出" } }, "news": "替换后的新闻" }
      ]
    }
  ],
  "interludes": [
    { "id": "badge", "window": ["1997-06-01", "1997-06-30"], "weight": 3, "cooldown_days": 5, "if": null, "text": "……" }
  ],
  "bgm": {
    "ai_mode": "playlist",            // off / playlist / free（旧的 "ai_tag": false 等同 off）
    "tracks": [
      { "title": "海阔天空", "artist": "Beyond", "mood": "紧张、不安" },          // id 默认为“歌手 - 歌名”
      { "id": "own", "title": "自制曲", "url": "https://example.com/own.mp3", "loop": true, "volume": 1 }  // url 可选
    ],
    "rules": [
      { "id": "fight", "keywords": ["枪声"], "regex": "开片|劈友", "track": "storm", "if": null }
    ]
  }
}
```

阶段、事件、插曲都可以加 `"bgm": "曲目id 或 歌名"`（或 `"stop"`）。事件还可以加 `"visibility": "show" | "title_only" | "hidden"`（只影响玩家日历）。

旧格式的曲目 `{ "id", "name", "url" }` 仍然可用：`name` 会被当作歌名。

- 日期一律写 `YYYY-MM-DD`（公历）。引擎支持任意年份（含公元前，如 `-0100-06-15`）。
- `affects` 的键可以是身份标签，也可以是角色 id；同一角色命中多个键时都会注入（先 id，后标签）。
- 显示格式占位符：`{y}{m}{d}` 年月日，`{mm}{dd}` 补零，`{w}` 星期（汉字），`{cy}{cm}{cd}` 汉字年月日，`{era}{ey}{cey}` 年号名 / 年号年数 / 汉字年数（元年显示“元”）。
- 法国共和历占位符（只用于显示，内部日期仍是公历）：`{ry}` / `{cry}` / `{rry}` 共和历年（2 / 二 / II），`{rm}` 月名（如葡月；年末补充日显示“无套裤汉日”），`{rmf}` 法文月名（Thermidor），`{rd}` / `{crd}` 日（7 / 七）。例：`共和历{cry}年{rm}{crd}日（{y}年{m}月{d}日）` → 共和历三年葡月一日（1794年9月22日）。只覆盖共和历实际使用的时段（1792-09-22 至 1805-12-31），范围外这些占位符为空。AI 的 `<time>` 标签仍然写公历。
- 涟漪模板占位符：`{who}{target}{choice}{type}{note}{event}`。没有模板时用通用文本。

### 条件表达式

```jsonc
{ "flag": "回归已完成" }
{ "choice": { "who": "shao", "event": "baht", "is": "撤出" } }  // who/event/is 都可省略；is 为包含匹配
{ "phase": "eve" }
{ "present": "kam" }                                          // 某角色在场（插曲抽取时有用）
{ "all": [ … ] }  { "any": [ … ] }  { "not": { … } }
```

`null` / 空对象表示无条件。用于事件的 `if`（不满足则事件不出现）、变体的 `if`、插曲的 `if`。

## 与 SillyTavern 的接口

实现时对照了 SillyTavern `release` 分支源码（`public/scripts/st-context.js`、`extensions.js`、`script.js`、`events.js`、`message-formatter.js`）。使用到的接口：

| 用途 | 接口 |
|---|---|
| 取上下文 | `SillyTavern.getContext()`（每次重新取，切换聊天后 `chatMetadata` 会换成新对象） |
| 注入 | `setExtensionPrompt(key, value, position, depth, scan, role)`；position 取值按源码中的 `extension_prompt_types`（`IN_PROMPT=0, IN_CHAT=1, BEFORE_PROMPT=2`），这个枚举没有从 context 导出，所以写成了常量 |
| 每次生成前更新 | manifest 的 `generate_interceptor` → `globalThis.worldChronicleInterceptor(chat, contextSize, abort, type)`（dry run 不调用），另外监听 `GENERATION_AFTER_COMMANDS` 保证提示词预览一致 |
| 消息事件 | `MESSAGE_RECEIVED` / `MESSAGE_SENT` / `MESSAGE_SWIPED` / `MESSAGE_EDITED`（参数为消息下标）、`CHAT_CHANGED` |
| per-chat 状态 | `chatMetadata.world_chronicle` + `saveMetadataDebounced()` |
| 全局设置 | `extensionSettings.world_chronicle` + `saveSettingsDebounced()` |
| 写入角色卡 | `writeExtensionField(characterId, 'world_chronicle', value)`；读取时先 `unshallowCharacter()` |
| 隐藏标签 | `messageFormatter.addHook(fn, { stage: BEFORE_REGEX })`；旧版没有这个 API 时，退回到渲染后用 `messageFormatting()` 重新渲染去掉标签的文本 |
| 弹窗 | `callGenericPopup(text, POPUP_TYPE.CONFIRM)`、`callGenericPopup(element, POPUP_TYPE.TEXT, '', { wide, allowVerticalScrolling })`（玩家日历）、全局 `toastr` |
| AI 帮我写 | `generateRaw({ prompt, systemPrompt, responseLength })`（返回字符串；`responseLength` 临时覆盖回复长度，生成结束后 ST 自己恢复）；取消用 `stopGeneration()`：它发出 `GENERATION_STOPPED`，`generateRaw` 内部监听这个事件中止请求。读卡用 `unshallowCharacter()`、`characters[characterId]` 的 `data.character_book` 与 `loadWorldInfo(data.extensions.world)` |
| 定期刊物 | 同样用 `generateRaw({ prompt, systemPrompt, responseLength })` 单独生成（不走聊天、不触发世界书扫描）；存 `chatMetadata.world_chronicle_periodicals`；写的时候换了聊天就丢弃结果；`getCurrentChatId()` 区分聊天 |
| 入口按钮 | 扩展菜单 `#extensionsMenu`（`list-group-item … extensionsMenuExtensionButton`，与自带的生图扩展同样写法）；输入框左侧 `#leftSendForm` |

**不确定 / 需要在真实 ST 里确认的地方：**

- `messageFormatter` 是较新的 API；旧版 ST 的退回方案（渲染后重渲染）只在模拟环境里跑过。
- 流式输出过程中，尚未闭合的 `<time>` 标签可能会短暂可见，消息完成后消失。
- 滑动 / 重新生成的状态回滚依赖“只记录最后一条处理过的消息之前的状态”，以及 interceptor 收到的 `type`（`swipe` / `regenerate`）和此时 `chat.length` 的关系；这是按源码推断的，需要实测。
- `writeExtensionField` 会立即把数据写到服务器上的角色卡；导出 PNG 卡时 `data.extensions` 应随卡导出，需要实测。
- AI 帮我写：`generateRaw` 的签名按 2026 年 10 月 `release` 分支确认（对象参数；旧版 ST 是位置参数，ST 会兼容并在控制台打警告）。不确定的点：`responseLength` 超过模型上限时，有的 API 会直接报错（可在“更多”里调小）；`stopGeneration()` 同时会停掉正在进行的聊天生成（在编辑器里一般没有）；部分后端取消后请求可能仍在服务器上跑完，插件会丢弃结果；思考模型的推理内容如果混进回复，解析时会去掉 `<think>` 块，但其他格式没有测试过。
- 群聊：映射按群聊保存，自动载入会检查群成员卡里的包；“写入角色卡”只支持单人卡。

## 已知限制

- 内部只用公历日期。显示上支持年号和法国共和历（1792—1805）；农历、架空历暂不支持换算。编辑器里的日期输入框用的是浏览器原生日期控件，不支持公元前年份（引擎本身支持，可以在 JSON 里写）。
- 编辑或删除**更早**的消息不会回溯重算世界状态（只有最后一条消息可以撤销重来）；删除消息也不会回滚。需要时请在面板里手动改日期 / 删除抉择。
- 涟漪只传一层（直接相连的人），不会继续往下传。
- 在场判定是简单的子串匹配，过短的别名可能误判；可以在面板里手动覆盖。
- 事件条件在注入时按当前状态求值：一个当初因条件不满足而被跳过的事件，如果之后条件成立且仍在余波期内，会重新出现。
- 依赖 AI 遵守标签约定；AI 不输出 `<time>` 时日期不会动，可以手动设定。
- 事件包保存在 ST 的扩展设置（settings.json）里，包很大时会让设置文件变大。
- 图床链接可能失效或有防盗链，放不出来时会提示。GD音乐台是第三方接口，随时可能变化或不可用；它返回的地址可能是 http，在 https 部署的 ST 上能否播放取决于浏览器。浏览器的自动播放限制无法绕过，首次播放可能需要点一下页面。

## 验证情况

- 引擎部分（`engine/`）有单元测试，开发时全部通过。
- 在 SillyTavern 1.19 里用示例剧本实际跑过：卡内剧本自动载入、`<time>` 推进日期、转折点只在时间窗口内提示、`<choice>` 记录、按日期切换背景音乐、聊天里隐藏标签。用真实模型回复过，AI 能按约定写出日期和选择，背景音乐能正常播放。
- 还没有在真实环境里专门测过的：日期一下跳很远时的确认弹窗、“只提醒一次”的事件、不同屏幕宽度下的面板排版、群聊。
- 0.2.0 新加的定期刊物（含《玉郎闲话》）和新的分页签面板、合并后的日历图标，只在模拟环境里跑过，还没有在真实酒馆里大量测试，用起来遇到问题欢迎反馈。
- 已知的小毛病：日子一下跳过很多天时，AI 偶尔会替玩家写出投票之类的选择。
